## 1. 研究问题与假设

1. **ACT 实机基线**：在任务 A 上，固定数据版本、观测、动作表示和评测预算后，ACT 能否形成跨 seed 可重复的实机成功率基线？
2. **SmolVLA 的适用边界**：在与 ACT 相同的数据版本、相机、状态输入、划分和回合预算下，SmolVLA 是否改善任务 B 的语言改写或 OOD 泛化，同时保持可接受的精细控制和延迟？
3. **动作结果模型**：给定当前观测、机器人状态、任务指令和候选动作块，结果模型能否提前识别有害失败，并在闭环介入时降低有害失败而不过度终止本可成功的回合？

假设是待检验陈述，不预注册正向结论。SmolVLA 或结果模型没有稳定收益时，应按本协议保留完整负结果。

## 2. 任务与结果语义

### 任务 A：多位置抓取放置

- 输入条件：从冻结的起始位置集合中选择一个对象位置，并指定目标区域或容器。
- 成功：在冻结的时限内抓取正确对象，将其完全释放并稳定留在目标区域；全程没有策略导致的安全停止、人工接管或越界动作。
- 失败：漏抓、抓取后掉落、放入错误区域、未完全释放、超时、策略导致的安全停止或人工接管。
- 尚未冻结：具体对象、位置分区、目标边界、稳定时长、时间限制和几何容差。

### 任务 B：语言条件分类放置

- 输入条件：从冻结对象集合与语言模板中生成指令，要求把正确对象放入指令对应的类别区域。
- 成功：执行对象与指令语义一致，且满足任务 A 的稳定放置和安全条件。
- 失败：选择错误对象或类别、未完成稳定放置、超时、策略导致的安全停止或人工接管。
- 尚未冻结：对象类别、同类新物体、训练语言模板、final test 改写、容器和时间限制。

### 任务 C

任务 C 不属于本预注册的正式范围。只有在 2026-10-04 gate 通过后，才能在查看任务 C 正式结果前建立单独 amendment；未通过时只能作为探索或展示，不纳入核心成功率。

## 3. 指标与统计方法

### 主指标

- 任务 A：逐回合二元成功率。
- 任务 B：指令一致的完整任务成功率，以及相同评测预算下 SmolVLA 与 ACT 的成功率差。
- 动作结果模型离线评测：AUPRC；同时报告 AUROC、Brier score、校准误差、失败类型召回率和可用提前量。
- 动作结果模型闭环评测：任务成功率与有害失败率为共同主结果；同时报告 rescue 和 harmful abort。

二元成功率报告 95% Wilson 置信区间。跨条件总体结果按预先冻结的任务 × 条件单元等权汇总，不按事后样本量或结果好坏改变权重；模型差值使用按这些单元分层的 bootstrap 置信区间。

### 次指标

- ID/OOD 成功率差、平均完成时间、人工接管率和冻结 failure taxonomy；
- 感知、模型、通信、动作发送和总闭环 P50/P95/P99 延迟；
- 控制周期抖动、空动作帧、动作队列耗尽、推理显存、吞吐与训练资源；
- 结果模型的覆盖率、校准、提前量、rescue、harmful abort 和额外延迟。

结果模型的当前工程目标仍是待冻结建议：基础策略成功率非劣下限不低于 -5 个百分点、harmful abort 不高于原可成功回合的 5%、明显有害执行约减少 30%、新增 P95 推理延迟约 15 ms 以内。它们必须在 validation 前结合硬件基线冻结，当前不得写成已达到结果。

## 4. 数据划分与冻结 gate

| 划分 | 唯一允许用途 | 访问与冻结规则 |
|---|---|---|
| train | 模型拟合 | 可按冻结清洗规则使用 |
| development | 实现调试、超参数和失败诊断 | 可重复使用，所有正式调参应有实验 ID |
| validation | 冻结候选 checkpoint、阈值和 gate 决策 | 访问须记录；不得回流为同版本 train |
| final test | 最终冻结方案的一次性报告 | 阶段 5 封存，阶段 6 才运行；不得用于任何选择 |

- 同一轨迹及裁剪片段不得跨划分；同一采集 session 和同一 source trajectory 的强相关回合必须位于同一划分。
- 正式采集前，最迟在阶段 1B 退出 gate 冻结：任务 A/B 对象、位置、背景/光照、相机布局、语言模板、成功容差、时限、划分规则和每个单元的最低回合预算。
- 阶段 5 结束前生成 final freeze Manifest，封存具体 final test episode/条件清单及其 SHA-256。
- final test 只在阶段 6 对冻结方案运行一次。策略本身造成的通信异常、安全停止、超时或相机失败计为失败，不能声明为无效回合。
- 只有与被评模型无关、且满足预先定义排除规则的外部故障才可标记无效；必须保留原始日志和视频，在汇总前登记原因，并按冻结顺序补跑。

## 5. 停止规则

1. 出现未解释越界、零位漂移、急停失效或其他安全协议触发项时，立即停止采集或闭环运行，修复并重新通过安全 gate 后才能继续。
2. 核心任务先各采 20 条并审计，再扩到 50 条；此后每新增 100 条通过审计的高质量示范，若 development 主指标提升小于 5 个百分点，暂停扩采并先做失败诊断。
3. 每个训练 spec 在登记实验 ID 前必须冻结 `max_steps`、`max_wallclock_seconds`、`eval_interval_steps`、`patience_evaluations` 和 `stop_metric`；不得根据 final test 延长训练。
4. SmolVLA 在基线配置后最多进行两轮预先登记、各自有明确假设的调参；仍无稳定结果时冻结为负结果，保留 ACT + 任务 ID 主线并转入动作结果模型。
5. 中断恢复只有在 experiment identity 完全一致时沿用同一 attempt；改变代码、配置、seed 或数据只能新建 experiment。旧 checkpoint 只能作为显式 `warm_start`，不得伪装成断点恢复。
6. 所有失败、停止和提前终止都必须生成结果摘要和 `stop_reason`，不得从索引中删除。

## 7. 禁止调整项

查看 final test 后，禁止根据结果调整或重新选择：

- 模型结构、checkpoint、seed、训练数据、阈值、action chunk 或归一化；
- 相机位置、标定、观测、动作表示、语言模板或任务容差；
- 数据清洗、划分、成功定义、主次指标、统计方法或 failure taxonomy；
- 回合预算、运行顺序、排除规则、条件权重或要展示的视频；
- ACT/SmolVLA 的资源预算或对照条件。

不得挑选成功视频代替逐回合结果，不得将 final test 失败回流训练后继续沿用同一 final test 名称。若实现缺陷使评测无效，应保留原结果和事故记录，修复后建立新预注册/冻结版本，并使用未接触的新 holdout；不得悄然覆盖。
